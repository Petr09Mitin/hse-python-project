# Запуск бота

Скопировать `.env.example` в `.env`, если своего `.env` ещё нет. Заполнить `TELEGRAM_API_KEY`
токеном BotFather и `OPENAI_API_KEY` ключом провайдера. Не добавлять `.env` в Git.

```dotenv
OPENAI_BASE_URL=https://api.neuraldeep.ru/v1
OPENAI_MODEL=qwen3.6-35b-a3b-noreason
```

Все три значения `OPENAI_BASE_URL`, `OPENAI_MODEL` и `OPENAI_API_KEY` обязательны для API-режима.
Одна модель используется для OCR изображений, определения чека, извлечения его данных и категорий товаров.
PDF с пригодным текстовым слоем читается без OCR; сканированные страницы направляются в модель.
Изображения и текст чеков передаются указанному API-провайдеру.

```sh
make up       # собрать образ и запустить бота с PostgreSQL в фоне
make logs     # смотреть журнал бота
make down     # остановить, сохранив данные PostgreSQL
```

`make run` запускает тот же состав сервисов в текущем терминале.
`compose.yaml` содержит только `app` и `postgres`. Compose читает `.env` автоматически;
локальные модели и OCR-зависимости не устанавливаются.

Для разработки `make install` устанавливает Python-зависимости и инструменты разработки через `uv`
(Python 3.12), без локального OCR.
`make lint` проверяет Ruff, `make format` форматирует, `make check` выполняет линтинг и тесты.

`make test` запускает полный pytest в одноразовом контейнере `app` с PostgreSQL
в отдельном Compose-проекте `receipt-bot-tests`. `TELEGRAM_API_KEY` и `OPENAI_*` очищены.
Тесты реальных локальных моделей и внешнего API пропускаются без соответствующих `TEST_*` переменных.
Обычный `make test` не подтверждает доступность провайдера или качество его распознавания.

Прежний локальный режим сохранён в Python-коде для ручных проверок; он требует отдельно
подготовленных OCR-зависимостей, моделей и сервера Qwen и не входит в Compose.
